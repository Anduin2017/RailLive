# RailLive 构建输入

`line-facts.json` 保存铁路类型、速度、线路别名等带出处的人工核对资料。修改时保留依据和链接。

在 `stop-times.json` 中，每条修正包含以下字段：

| 字段 | 内容 |
| --- | --- |
| `trip_id` | 原始 GTFS 的班次 ID |
| `stop_sequence` | 原始 GTFS 的停站序号 |
| `stop_id` | 原始站码 |
| `before` | 原计划到达、发车，两个 GTFS 时刻字符串 |
| `after` | 修正后的到达、发车 |
| `source` | 可核对的出处及适用说明 |

一条修正适用于该班次在当前 GTFS 中的所有开行日。跨日时刻用 GTFS 格式，如 `25:03:00`。更新上游版本时，编译器会拒绝已失配的修正和倒序时刻，避免静默覆盖上游更新。修正只应用到构建工作目录中的副本，原始归档可继续对账。

## 原始资源

`tools/build_from_source.py` 中的 `SOURCE_FILES` 是完整清单。原始输入目录包含：

- `data/` 内的 GTFS 发行文件、许可、线路表、同版本坐标参考和采集的原始站线数据。
- `map/` 内的原始矢量瓦片、地图样式、字形、精灵、覆盖信息和轨道细节。

当具有再分发授权时，可以按这个布局将固定版本的输入放入 `inputs/raw/`，从仓库本身完成重建。输入出处及再分发要求见 [第三方说明](../THIRD_PARTY.md)。SQLite 索引、对账报告、拆分底图和时空片均由编译生成。
