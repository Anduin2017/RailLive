# 快照维护

基础快照为 2026-11-17，普速时刻表于 2026-11-22 更新。维护前，在仓库根目录运行 `python3 tools/prepare.py`，然后进入 `build/app/` 执行生成命令。这里的 `data/`、`map/` 和 `space-time/` 都指向所选快照。更新时使用独立的可写工作快照并保留原始输入，验证通过后再部署。

## 构建输入

运行包用于部署。完整重建还会用到运行包之外的输入，请保存在自己的工作快照中。

| 目录 | 需要保留的输入 |
| --- | --- |
| `data/` | 上游发行版的 `output_gtfs.zip`、`lines.json`、发行信息、许可、同版本坐标参考、配套的 12306 时刻表补充包，以及本地带出处的 `line-facts.json` |
| `data/cnrail-source/` | 已采集的站卡、线路详情和发现记录，供导入、建图、审计使用 |
| `map/` | 原始 `tilejson.json`、`style.json`、已改成本地资源地址的 `offline-style.json`、补充点位、轨道细节及覆盖信息 |

## 数据覆盖

- 铁路底图来自[中国铁路地图](http://cnrail.geogv.org/zhcn/)的[矢量瓦片](http://railmap.geogv.org/data/wtrans2-20261102.json)，保留原图层和颜色。离线范围为东经 69°–136°、北纬 17°–56°，保存了缩放 1–8 级共 2,448 块原生瓦片。继续放大时通常复用第 8 级瓦片。康山联络线另外保存了[原站第 11 级瓦片](http://railmap.geogv.org/data/wtrans2-20261102/11/1688/829.pbf)的轨道，线路所坐标来自原站站点详情，离线也可查看。中文地图文字使用设备上已安装的中文字体。
- 基础时刻表来自 [Chinese Railway GTFS 2026-11-17](https://github.com/wensimehrp/chinese-railway-gtfs/releases/tag/gtfs-20261117-101334)，该版含 **11,854 个车次号、3,157 座时刻表车站（原始 3,180 个站码）**，包含 110,325 条停站时刻。其中 9,254 个车次有线路几何，其余由区域索引逐区间补配推测径路。车次号、停站和开行日期以该快照为准，和原站的数据版本、覆盖范围可能不同。大于 24 小时的 GTFS 时刻显示为次日或之后，如 03:10 (+1)。
- 普速换号补充包按始发日从 2026-11-25 起生效，保留之前的跨夜车次。以铁路 12306 的按日车次清单、开行标记和逐站时刻核对，同号不同内部版本按日期消歧。快照有效期至 2027-02-02，远期覆盖取决于采集时已公布的计划。缺少可核对的开行日、停站时刻或车站位置的记录列在补充包 `source.json` 中。
- 地图叠加层用 2,570 个同名车站拟合坐标转换，使 GTFS 路线与原站瓦片对齐。底图与时刻表来自不同快照，个别站点仍可能有位置误差。
- 搜索完整车次号直接查看时刻和线路。也可搜车次前缀、车站名或线路名，点击地图车站和所选线路的停站点查看信息。
- 车站详情分为概览、列车和统计。概览按原站站卡的 kid 读取接入线路，每行保留线路 eid、简称、颜色、邻站及方向，点击直接进入该 eid 的详情。源站站卡与 GTFS 优先以电报码和站名关联。缺少电报码时，仅在两侧站名均唯一且校正后点位相距不超过 200 米时补充关联。缺少原站关系时，界面会标明 GTFS 配套线路表来源。列车列表显示运行区间、本站到达和离开时间，可按始发、经停和终到筛选。时刻以本地快照为准。
- 车站统计展示始发站和终到站排行、24 小时到发量、停靠类型占比、起终点组合和经停车停留时长。点击图表项可查看相应列车。统计单位是快照中的停靠记录，一趟车在本站的一次停靠算一条。筛选线路时，可按进站、离站或任一侧统计。线路归属用列车轨迹与本地瓦片匹配，或用只属于一条候选线路的相邻站判断。线路证据不足或冲突的记录显示为待确认，不纳入所选线路图表。
- 点地图上的线路名称或车站详情中的接入线路，可以高亮轨道并按站序编号。发行包附带的线路表由上游从 jprailfan.com 采集，收录 759 条线路。GTFS 自身的 route_id 在本发行版中是车次号。按 ID 采集的车站和线路原始记录保存在 `data/cnrail-source/`，服务读取打包后的 `data/cnrail-graph.json.gz`；早期线路归档 `data/cnrail-lines.json` 作为补充来源，提供铁路类型、线路总数、电气化、设计时速和原站站序，以源数据实际收录的字段为准。两份站序有差异时可以切换。另行核实的线路类型、设计时速、全线长度及出处保存在 `data/line-facts.json`。原站关系优先展示对应 eid 的技术分类。GTFS 补充记录仅使用已核实资料或已通过站序核验的原站类型；线路名明确写有“联络线”时也可按联络线筛选，技术类型缺失时以此显示其用途；其余缺失类型显示为未知。底图多段共用一个名称时提供按 ID 区分的候选线路。
- 底图保留 OpenStreetMap contributors 和中国铁路地图的署名。基础 GTFS 由 wensimehrp（Jeremy Gao）发布，采用 CC BY 4.0。普速换号补充数据来自铁路 12306。原始 GTFS、发行信息和许可保存在 `data/`，容器通过只读挂载访问运行快照。

## 维护

- `python3 import_gtfs.py` 从 `data/output_gtfs.zip` 和 `data/lines.json` 重建 SQLite 索引。
- `python3 download_map.py --maxzoom 8` 可补下载当前版本的地图文件，已经下载的文件会跳过。瓦片来源以 `map/tilejson.json` 为准。
- 更新离线底图后，运行 `python3 build_basemap_tiles.py` 生成独立的铁路与地理背景瓦片。
- `python3 index_rail_map.py` 从离线瓦片重建线路视野和站点位置索引。`map/rail-extra-points.json` 保存原站提供的补充坐标。京沪高速线底图缺失的末段以快照中的 G25 运行径路补齐。京哈高速线全线详情按事实文件里的区段配置读取京沈段和沈哈段站序，保留各段里程。

### 原站资料重建与对账

1. 运行 `python3 collect_cnrail.py`。采集器从本地瓦片的铁路站点图层读取 kid，沿站卡的线路 eid、邻站 kid 和线路站序继续采集。请求限速，成功的原始响应按 ID 缓存，重跑可续传。更新已有记录时可加 `--refresh-since YYYY-MM-DD`，成功取得新记录后才替换旧文件。
2. 运行 `python3 collect_cnrail.py --discover`。使用仍未匹配的 GTFS 站名及线路名发现更多候选 ID。搜索结果仅用于发现，关联证据单独核验。
3. 在原站站卡采集完成后，重新运行 `python3 import_gtfs.py`，用本批站卡核验时刻表中的候选站码别名。随后运行 `python3 build_cnrail.py`。保留各来源的独立站序，比较 GTFS 与原站的完整站序以识别异名。底图同名或别名候选需要再用轨道附近的原站点位验证，匹配证据随快照打包。
4. 运行 `python3 audit_cnrail.py`。逐行核验源站关系与本地详情、GTFS 原始停靠时刻和车站合并结果，输出 `data/cnrail-audit.json`。运行中的服务也提供 [离线对账报告](http://127.0.0.1:8080/api/source/coverage)。其中分别列出缺失详情、未匹配实体、底图待核轨道以及原站记录之间的差异。先在候选容器验证，再替换本地服务。

例如深圳站的原站站卡列出广深线，原站京九线详情止于常平；GTFS 配套京九线站序另含深圳东、深圳、九龙。原站站卡打开其线路 ID，线路详情提供独立的 GTFS 站序对照。

GTFS 站点使用 WGS84。构建时逐站比对同一发行标签的 `coordinates.csv`；上游对缺失的站名会用相邻站点插值。插值、同名多点和坐标不一致的记录不参与几何匹配。能以原站 ID 定位时，站卡和列车标记优先采用该点位。坐标参考可用 `python3 gtfs_coordinates.py` 更新，二次发现阶段也会按本地发行标签校验。参见[该版本生成器](https://github.com/wensimehrp/chinese-railway-gtfs/blob/gtfs-20261117-101334/gen_gtfs.py)。

### 更新运动模型和时空片

在完成时刻表、底图和原站资料对账后，按依赖顺序生成以下产物。生成运动曲线需要 Node.js。全国重算时请预留旧版与候选版本同时占用的空间。

```sh
python3 build_relations.py
python3 region_live.py
python3 space_tiles.py
python3 station_symbols.py
python3 audit_live.py
```

生成器会把运行片按地理网格和五分钟时间窗写入版本目录。客户端先读取 `space-time/manifest.json`，再获取对应版本的几何、开行日历和运行片。如果分发到静态文件服务，应先放好版本目录，再切换清单。`.gz` 文件按原始字节提供，浏览器负责解压。

从仓库根目录验收当前快照：

```sh
python3 -m unittest discover -s tests/snapshot -p 'test_*.py'
python3 tests/snapshot/verify_space_tiles.py
```

回归覆盖跨日班次、同线车序、路径补配与到发时刻。全量对账会解压运行片和几何块，请预留数分钟。扫描结果写入快照的 `data/live-audit/` 目录，包含 JSON 摘要和 CSV 明细。完整运行快照的导出方式见 [README](../README.md)。
